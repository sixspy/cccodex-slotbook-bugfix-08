# 占位审计说明（BUGFIX-08）

> 钉死日期：2026-11-22。当日不得改口；后续任何偏离须在文末「偏航登记」留痕，走偏即记「占位审计偏航」。

## 1. 缺陷口径

- 现象：占位服务 `POST /api/holds` 落库 `holds` 成功，但未写 `audit_trail`，审计流水没有写者与档码，事后追责对不上。
- 同源问题：两人同档争用时，`require_lock` 写入的 `contention_log` 在请求失败路径随事务回滚，争用痕丢失（后到者连痕都没留）。
- 掩盖手段（须拆除）：`audit_svc` 曾过滤 `action='hold_create'`，让缺审计在审计页不可见。

## 2. 钉死方案：甲路径（同事务），禁止混用乙路径

本仓只有这一条正确性口径，**甲、乙两边不得混用**：

- **甲路径（采用）**：同一数据库连接、同一事务内，先插 `holds` 占位行，再写 `audit_trail` 的 `hold_create` 流水，单次 `commit` 同成败。
  - 任一步失败 => `rollback`，占位零增、审计零增。
  - 成功 => 接口同时返回 `hold_id` 与 `audit_id`，**禁止只返回占位号**。
- 乙路径（先写审计草稿再原子切换占位与已签发审计，失败草稿作废）**不采用**，本仓不得出现审计草稿/状态切换表或双段提交写法。

边界：本说明只约束占位服务 `POST /api/holds`。候补晋升 `waitlist_svc.promote_wait` 沿用既有 `waitlist_promote` 同事务流水（payload 带 `hold_id`），不在本次改动面，禁止顺手改出第二套口径。

## 3. 不变量

1. **占位 ⇔ 审计同成败**：经占位服务产生的每个 `holds` 行，必有同事务 `hold_create` 流水；事务失败则两边都不存在。
2. 流水字段：`actor`=写者账号、`action`='hold_create'、`target`=当事人 `party_key`、`payload` 含 `slot`（档码）、`hold_id`（回链占位）、`seats`。
3. **争用留痕**：抢档锁失败返回 409 时，`contention_log` 必须先提交留存；占位与审计均零增。
4. 审计页不得再过滤 `hold_create`，缺审计要如实可见，禁止掩盖。

## 4. 五处同态（同一事实五个只读面，数字须对得上）

| 面 | 接口/视图 | 同态内容 |
|----|-----------|----------|
| 占位页 | `GET /api/holds`、占位单视图 | 每条占位带 `audit_id`（互证审计号），无审计显示「缺审计」 |
| 审计页 | `GET /api/audit`、审计争用视图 | 含 `hold_create`，展示写者、动作、当事人、payload（档码/占位号/席）、时间，不再过滤 |
| 余席 | `GET /api/slots`、档期盘视图 | `free_seats = capacity - booked - 占位中席数`，与占位服务容量判定同源 |
| 对账页 | `GET /api/reconcile`、对账互证视图 | 每档列开放占位数、已互证占位数、`hold_audit_ok`；汇总 `hold_audit_all_ok` |
| 互证页 | `GET /api/proof/{party_key}`、对账互证视图互证区 | 当事人占位/正式册/候补与审计流水同源返回，审计条数可对上 |

历史种子占位 `P-HOLD1`（fixtures/holds.json）本身无审计，是同缺陷族的历史数据；对账页与占位页对其如实显示「未互证/缺审计」，不做掩盖。修复后新产生的占位必须全部同态。
